# dsh-writing-slots

写作四槽位。把「题材设计 → 大纲 → 章节 → 审阅」里的**后半段**拆成四个可独立调用、可单独替换的模块，每个模块有自己的输入契约与输出契约。

| 模块 | 触发时机 | 输入 | 输出 | 人工门禁 |
|---|---|---|---|---|
| **Style Anchor**（文风锚点） | 项目初始化，只跑一次 | 3—5 篇样本（总计 ≥5 万字）+ 体裁标签 | `style-guide.md`（句长基线 / 比喻指纹 / 禁忌清单） | 人审「这像不像我写的」 |
| **Chapter Pack**（单章包） | 每章动笔前 | 章号 + 本章任务 + 字数区间 | 初稿正文 | 人审章尾钩子和情感落点 |
| **Review Pass**（审稿通道） | 初稿完成后，独立会话 | 初稿 + 设定快照 + 上一章摘要 | 结构化问题清单（JSON） | 人决定哪些改、哪些不改 |
| **Reader Simulation**（读者通道） | 初稿后，**审稿之前** | 初稿 | 三个读者的第一人称反应 + 三个锚点 | 反馈是信息不是命令 |
| **De-AI Polish**（去味层） | 审稿修改后，最后一刀 | 修改稿 + 禁忌清单 | 润色稿 + `change_log` | 人通读「有没有不像我的句子」 |

上游还有两个初始化模块（正文动笔前跑）：

| 模块 | 触发时机 | 输入 | 输出 | 人工门禁 |
|---|---|---|---|---|
| **World Builder**（世界观） | 初始化；正文动笔前 | 题材 | `world-bible.md` | 人审「每个设定是否都有代价和限制」 |
| **Character Designer**（人物） | 初始化；新角色登场前 | 角色名 | 人物卡 | 人审「三者的冲突是否真的成立」 |

## 核心分工：代码管判据，模型管写作

这个插件不自己去调模型。它做的是**渲染提示词**，并且**把能算的判据全算完**：

| 谁做 | 做什么 |
|---|---|
| **代码** | 统计句长/节奏/感官/比喻；筛禁忌清单；跑去味规则并给逐条证据；校验审稿 JSON 契约；强制上下文隔离；复验改写结果 |
| **模型** | 写正文、改写违规句 |

这样「有没有做到」是可验证的：数字能验算，例句能定位，改写前后能重扫计数。模型说「已润色」不算数。

## 四个工具

### 槽位模板是声明式的

模板用 `{槽位}` 占位，**渲染前先过契约校验**：

```yaml
ROLE: chapter_drafter
CHAPTER: {chapter_no}

CHAPTER_TASK:
  事件：{chapter_task.event}
  停在：{chapter_task.stop_at}

STYLE_GUIDE（固定前缀）:
{style_guide_digest}
```

支持 `{#if}` / `{#unless}` / `{#each x as y}`。缺必填槽位会**直接失败**，模板里写了但没声明的槽位也算错（拼错名字不报错的话，它会静默渲染成空字符串，模型自己编一个补上，你还以为它照做了）。

## 项目布局

插件按目录约定读项目（找不到就如实说找不到，不猜）：

```
novel/
  style-guide.md        ← Style Anchor 产出
  全书大纲.md            ← bible 骨架
  卷纲/卷NN.md
  细纲/第NNNN章.md       ← 解析出章节任务（事件/爽点/钩子/不得违反）
  前情提要.md            ← 每章一条，取目标章的**上一章**（不是文件最后一条）
  chapters/第NNNN章-*.md
  chapters/草稿/         ← 先落草稿，润色后发布
```

细纲里字段的映射：

| 细纲 | 槽位 |
|---|---|
| 任务 | `chapter_task.event` |
| 爽点 | `chapter_task.desired_effect` |
| 钩子 | `chapter_task.stop_at` |
| 不得违反 | `avoid_list`（按 `；` 拆开） |

缺 `任务` 或 `钩子` 时**直接报缺**，不拿别的字段顶替。

## 上游：世界观与人物

规格里这两条的要求是「不要一次『生成』，要『逼出代价』」。所以它们不只是模板，还配了**结构校验**——模型很容易交出一份「看起来完整」的东西，缺项被它自己圆过去。

### World Builder

必需七节：基础设定 / 力量体系 / 社会结构 / 近百年重大事件 / 隐藏规则 / 普通人日常场景 / 自检。

代码查的硬指标：

- **力量体系必须写明「使用代价」与「限制」**——这是加粗的那条。两个词都查，缺一就打回。一个没有代价的力量体系，写起来必然悬浮。
- 隐藏规则 **≥2 条**、日常场景 **3 个**（数量不足打回）
- 每节 **150—300 字**（不足给提醒）
- 「自检」一节不能走过场

### Character Designer

必需六项：表面欲望 / 真实需求 / 致命缺陷 / 内心独白（约 100 字）/ 过往创伤（冷静笔触）/ 标志行为（愤怒·恐惧·狂喜三档）。

代码查：

- 六项齐全，**三档情绪缺一档就打回**
- 内心独白在 60—160 字之间（规格说「约 100 字」，给宽容区间）
- 「过往创伤」出现「痛不欲生」「撕心裂肺」这类词会提醒——规格要求冷静笔触

**有一件事机器判不了**：表面欲望 / 真实需求 / 致命缺陷三者是否**真的冲突**。那是理解题，所以校验结果里会明写这一条需要人读一遍，而不是假装查过了。

## 三处刻意的设计

### 1. 审稿的上下文隔离是强制的

`Review Pass` 只放行 `draft` / `bible_snapshot` / `prev_summary` 三个槽位，多给的一个都拒绝：

> 破坏了上下文隔离：不允许把 style_guide 交给审稿模块。

理由是不护短：审稿不知道作者想写成什么样，就没法替作者找理由。把风格指南塞进去，审稿就会开始点评文笔，而要求明说是「不评价文笔好坏」。

审稿模板里**不引用任何带 style 的槽位**，也没有可选槽位 —— 少一个入口就少一条泄漏路径。

### 2. Style Anchor 的关键指标是统计出来的

「句长基线」「段落节奏」「感官倾向」「比喻指纹」全部从文本直接统计，模型只负责挑例句、写禁止项。锚句的选择是**确定性的**（按密度/长度就近挑），所以同一个样本每次跑出的锚句一致，可复核。

样本不达标的处理是**拒绝产出**，而不是给出一个凑数的基线：

```
样本不达标：样本篇数不足：给了 2 篇，要求至少 3 篇；样本总字数不足：412 字，要求至少 50000 字
```

拿两千字统计出来的「基线」会把后面的写作带偏。

### 3. 禁忌清单的判据是「样本里 0 次命中」

要求写的是「该样本中从未出现的句式或词汇类型」。所以做法是：先给一批常见 AI 腔句式，逐个在样本里数；**数为 0 的才进禁忌清单**。出现过的就不该列为禁忌 —— 那是在否定作者自己的写法。

去味层只跑清单里有的规则：作者本来就在用的句式，不该被当成毛病。

## 读者通道：请三个具体的人来读

这是和 Review Pass **并列**的另一条通道，不是它的替代：

```
Chapter Pack 出初稿
      ├── Reader Simulation（三个读者，读反应）→ 第一人称体温
      └── Review Pass（冷面编辑，查一致性）   → JSON 问题清单
```

**顺序有讲究：读者先跑。** 审稿会改稿，改完的稿子已经不是「读者第一次翻开」的东西了。读者插件要模拟的正是那第一次。

### 为什么读者不是「一个评估维度」

要求里那句说得很准：读者插件不是替你判断好不好，是「替你在你不在场的时候，当一次那个会跑掉的读者」。

所以读者被拆成**三个具体的人**——「目标读者画像」那种抽象说法没用，模型会把它演成一个礼貌的评审。要给它生活场景和偏见：

| 读者 | 测什么 | 他会怎样 |
|---|---|---|
| **小陈**（28 岁通勤） | 会不会继续读 | 一章超过五分钟没抓住就切去刷短视频 |
| **阿岚**（35 岁，读两遍） | 会不会记住 | 最恨前后矛盾，最容易被「早有伏笔」击中 |
| **老周**（45 岁，读三十年） | 有没有被糊弄 | 解释就是冒犯，总结就是侮辱 |

人格写的是**生活习惯，不是参数**——不写「注意力持续时间：短」，写「一章超过五分钟没抓住他就切去刷短视频」。模型对具体生活的模拟远好于对抽象参数的执行。

### 输出的铁律：体温，不是指令

`HARD_RULE` 写在提示词最前面，三条钉死：

- **禁止文学批评术语**（节奏、弧光、张力、信息密度…）——读者不这么说话
- **禁止修改建议**——想说「该改」就改写成「我希望发生什么」
- **允许「没感觉」**——本章没有一句话让你停一下，直接说「没有」。空的 `memorable_line` 是**有效信号**，编出来的才是污染

输出契约：`first_person_reaction` + 三个锚点 `continue_reading`（只有 yes/no/maybe，不给中间态）、`memorable_line`、`skip_urge_location`。

校验查的是**有没有越权**，不是「说得对不对」——读者没有对错，只有反应。实测：

```
用了文学批评术语：节奏、弧光 —— 读者不该这么说话
给了修改建议（「建议修改」）—— 读者只说反应，不说该怎么改
```

### 汇总判断

三个人的反应合起来才有意义：

- 三个都说 no → 大概率结构问题
- 只有小陈说 no，另两位有记忆点 → 可能这章本来就偏静，**要不要为留存牺牲质地由你定**
- 都没想放下但没人记住句子 → 读得下去，留不下东西

插件永远不说「这章不行」，它只说「小陈在这儿走神了，阿岚记住了这个动作，老周在这儿翻了个白眼」。改不改是作者对读者的承诺问题。

### 跑法

**每位读者单独跑一次**，不要在同一个会话里让他们轮流说——那样会互相影响，也就测不出各自的真实反应。

## 故事引擎：把「水场景」变成可拦截的输入错误

四样东西，共同点是都能做成**可拦截的输入校验**，而不是写完再主观判断。

### 压力反应表（人物级）

读者记住一个人物，几乎不是因为外貌性格，是因为**他在某个压力下做了一个出乎意料但完全合理的决定**。所以四档压力各写一行：

```
档位 1（轻微不顺）：嘴上不饶人，手上照做
档位 2（利益受损）：先退一步，回去算账
档位 3（被逼到墙角）：突然沉默，然后用最平静的语气说最狠的话
档位 4（失去最重要的人）：不哭，开始整理东西
隐藏动机：所有强硬都是在预防被抛弃
共情锚点：在群里发完消息后反复看有没有人回
```

**注入时只给当前档位那一行**（+ 隐藏动机 + 共情锚点），不是把四档全塞进去——模型拿到太多「人物资料」就会写出一段人物小传式的叙述。

**档案层（外貌/背景/关系）不进正文注入，只给审稿用。** 这条有测试锁着。

### 信息差矩阵（章级，每章必填）

章尾钩子的本质就是那一行「配比变化」：

- 读者知道而人物不知道（悬念/焦虑）
- 人物知道而读者不知道（谜团/好奇）
- 双方都不知道（未知恐惧）

`intended_shift` 三条全空 → 打回，并说明「本章结束时读者知情状态没有变化，这一章可以被跳过」。

### 情感温度曲线（卷级）

**连续三章不得同温**——连续同温是读者流失的高发区。这条是硬警告。

### 欲望-障碍-代价（场景级）

这是把「水场景」从主观判断变成**可拦截的输入错误**：

```
cost_if_fail 不具体（「失去一切」）→ cost_not_concrete，拒绝生成
desire 抽象（「想变强」）        → desire_not_concrete
obstacle 抽象（「命运」）        → obstacle_not_concrete
结果「得到」但没付出代价          → cost_free_scene，无代价场景
```

## 确定性检查

不需要模型判断，纯规则，所以放在渲染之前当门禁：

| 查什么 | 为什么 |
|---|---|
| **截断** | 结尾没有句末标点、引号没关。读者读到一半突然没了，比写得差更劝退 |
| **工程词泄漏** | 「本章」「伏笔」「爽点」「信息差」跑进正文。这是插件化写作特有的翻车方式，人工读稿反而容易漏 |
| **占位符残留** | `{槽位}`、`TODO` 没被替换 |

`critical` 一律阻断。`allowedTerms` 可以放行项目本来就在用的词（比如人物对话里真的说了「伏笔」），避免一刀切误伤。

## 去味的七条规则

代码检测 + 复验，模型改写：

1. 禁止段首连续以同一人称代词开头
2. 禁止「仿佛 / 似乎 / 宛如」这类明喻引导词
3. 禁止「一种……的感觉 / 莫名的……」这种抽象情绪句式
4. 禁止对话后除「说道 / 问道」外的**描述性**标签
5. 短句占比不得低于 Style Anchor 的基线
6. **禁止过度解释**——规格说 AI 味的根源不是词汇，是「过度解释和对称感」
7. **禁止对称感**——重复标记的排比、对仗式收尾

### 允许清单（规格里的反向约束）

规格除了禁止项，还明写了两条**允许**：

- **允许不完整的句子**（无主语句、独词句、断句）
- **允许人物说废话**（寒暄、重复、跑题）

这两条是反向约束：去味时不能把断句和闲话当毛病改掉——那恰恰是人味所在。所以扫描结果里会数出「有多少处属于允许范围」，并写进提示词明确告诉模型「这些不要改」。

### 第 7 条踩过的坑

「对称感」第一版写成「任意三个逗号分句」，结果**真稿每章命中 10.23 次**——中文叙事里「他站起来，走过去，推开门」太常见了，那不是 AI 腔。

收紧成**重复标记的排比**（三个分句用同一个词领起）后降到每章 0.64 次。同时修了一个正则 bug：第三个分句后面要求必须是逗号，导致「他看见了田，看见了稻，看见了水。」这句典型的排比**完全漏掉**。

还有一处一致性 bug：风格锚点的禁忌表用的 id 是 `parallel-stack`，去味规则用的是 `symmetry` —— id 对不上，**禁忌清单的过滤会静默失效**。现在两边 id 对齐，并有测试锁住「每条去味规则都能被禁忌清单过滤」。

这条链的意义：作者本来就在写对仗，所以 `symmetry` 在他的样本里会出现 → 不进禁忌清单 → 这条规则对他**不生效**。规则不该否定作者自己的写法。

### 第 4 条踩过的坑

第一版写成「闭引号后 `X道`」，结果在真稿上 50 章误报 124 处 —— `知道`、`一道`、`岭道` 全被当成对话标签。「X道」在中文里太常见了。

改成两道判定：

- **靠引号配对**：按奇偶判断哪个是闭引号。`"不知道` 里的引号是**开**引号，直接跳过。
- **只拦带方式状语的**：`他说`、`吴常说` 是普通归属语，放行；`她低声道`、`裴典淡淡道` 才是 AI 腔 —— 后者在描述「怎么说」，而不是交代「谁在说」。

改完在 50 章真稿上只剩 3 处命中，且**都是真问题**。

### 标题栏与返回

每个页签都有自己的**标题 + 说明 + 面包屑**，左上角有「← 返回」：

```
[← 返回]   指令库                                 设置 › 写作槽位 › 指令库
           勾选条目，组合成最终写作指令
```

- 返回走**历史栈**（最近 10 页），不是简单回首页
- 在写作槽位且无历史时按钮置灰
- 当前页签记在 localStorage，下次打开接着用

### 一个只有真机才暴露的 bug

点「指令库」时**整个面板消失**。原因：

```js
const [lib, setLib] = useState(null)
...
if (lib === null) return h('div', ...)   // ← 提前返回
const doCompose = useCallback(...)       // ← hook 在它后面
```

第一次渲染数据还没到 → 提前返回，跳过 `doCompose`；数据到了 → 多一个 hook。
React 抛 **#310（Rendered more hooks than during the previous render）**，并**卸载整个组件树**。

单测和 mock 渲染都测不出来——mock 的 `useState` 不校验 hook 数量。

现在 `verify-client.mjs` 第十节会静态扫描：任何组件「提前返回之后还有 hook」都会被打回。

**教训**：组件里 `if (...) return` 之前必须放完所有 hook。这是我的错，而且只有真开浏览器才看得见。

## 设置页面板

装好并重启后，设置页左侧导航会多一项「**写作槽位**」。

面板顶层有六个页签：**写作槽位**、**指令库**、**阅读器**、**工作目录**、**小说网站**（常驻），以及**自动续跑**（只在启用时出现）。

写作槽位页签是两栏：

- **左栏**：七个槽位的卡片，带就绪状态（缺 `style-guide.md` 或 `world-bible.md` 会显示未就绪）
- **右栏**：选中模块的**契约**（必填 / 自动注入 / 可选）、操作表单、以及渲染出来的提示词（可复制）

每个模块的字段与动作写在一张表里（`PANELS`），加一个模块只要加一条，界面自动出来。

面板**不代跑模型**。它渲染提示词、跑统计与结构校验，把结果摆出来；写正文、改写句子由调用方拿着提示词去做。

本文档、审稿结果、去味改写的校验也在这里：贴进文本框点「校验」/「复验」即可 —— 输出契约是 JSON、强制四维度三色灯、拒绝非原子指令，这些都在代码里查。

## 安装

```bash
dsh plugin --profile web add link:/path/to/dsh-writing-slots
```

装完要**两件事**，少一件插件都不会加载：

1. 依赖进 `package.json`（`plugin add` 会做）
2. 名字进 `dsh.profile.bundles`（**不会自动加**，要手动加）

然后重启 DSH。插件目录不在 HMR 监视范围内，改代码必须重启才生效。

## 工作目录

插件所有产出都落在**一个工作目录**里，不再散在会话 cwd。设一次，之后所有槽位默认都用它。

解析顺序：**显式传入 → 插件配置 → 环境变量 → 会话 cwd → 默认落点**（`~/dsh-writing`）。然后在其中定位真正的项目根——兼容两种布局：

- 工作目录本身就是项目（里面有 `细纲/` 或 `章节/`）
- 工作目录是工作区，项目在 `novel/` 子目录下

### 为什么要有这一层

以前每个入口各自 `projectDir ?? 会话 cwd`，结果**换个会话就可能把同一本书写到别处去**。要「后续内容都在工作内容区完成」，得有一个唯一来源，而不是每处各判断一次。

### 记住的路径失效时怎么办

界面会**明说原因**，并在工作目录页签给出「重新检查记住的路径」按钮 —— 目录恢复可用就切回去，**不用重启**。

失效时显示的是真实错误，不是一句「不可写」：

```
记住的工作目录不可用：/home/wsn/文档/dsh/本地演示/novels/插件目录拆解
· 这个目录不可写：EACCES permission denied ...
  尝试写 .dsh-write-probe-12345 失败，code=EACCES
  目录可读，有 44 个条目
现在临时用：~/projects/deepseek-harness（来源 session-cwd）
```

**两个真踩到的坑**（都是这个「不可写」引起的）：

1. **写探针的 cleanup 失败被当成「不可写」**：旧实现把 `writeFile` 与 `unlink` 放同一个 `try`，`unlink` 抛错就误报。目录明明可写，却被判死。
2. **失效会永久定格**：旧实现只在第一次调用时检查记住的路径，一旦那次失败，`workspaceDir` 就被钉成 session-cwd，之后即使目录恢复也**永远回不去** —— 界面表现就是「指令库一直是空的」，而且没有任何提示。

现在：记住的路径**每次调用都重试**，恢复可用就自动切回。

### 记住用哪个目录

设置一次后**记在 `~/.dsh/dsh-writing-slots/workspace.json`**，重启 DSH 自动恢复。

**为什么不写在工作目录自己里面**：那等于把钥匙锁在屋里——下次启动你正是因为不知道屋在哪，才需要这份配置。所以工作目录里那份 `.dsh-writing-slots.json` 记的是**这个目录的元信息**，而「用哪个目录」记在 DSH 主目录。

界面上会显示这个路径是**哪来的**：

| 来源 | 含义 |
|---|---|
| `remembered` | 上次记住的（重启后正常就是它） |
| `set` | 刚手动设的 |
| `explicit` | 调用时显式传的 |
| `env` | 环境变量 `DSH_WRITING_WORKSPACE` |
| `session-cwd` | 会话工作目录 |
| `default` | 默认落点 `~/dsh-writing` |

记住的目录被删掉或挪走时不会静默回退，会带一个提示说明哪条路径失效了。界面上也有「忘掉」按钮。

### 标准目录结构

```
细纲/     每章细纲           素材/    榜单、灵感、参考资料
章节/     正文（草稿/ 先落）  拆文库/  拆解出的内容
卷纲/     卷级大纲           样本/    Style Anchor 的语料
设定/     世界观、人物卡、style-guide.md
导出/     交付产物
```

`action=init` 建结构，幂等（已存在的目录不动）。

## 小说逻辑图：素材 → 拆解 → 图 → 素材库

这是主链，起点在**写作槽位**页签：

```
写作槽位从工作目录提取本地素材
      ↓  1. 从工作目录提取素材（素材/拆文库/样本/设定）
子智能拆分阅读（模型读素材，按槽位功能点拆开）
      ↓  2. 生成子智能拆解提示词 → 交给模型跑
结果填进槽位对应功能点
      ↓  3. 把 JSON 收成逻辑图（校验 + 存盘）
一键生成完整逻辑图
      ↓  4. 图 → 指令库条目
存进指令库，当后续写作的真实素材库
```

### 整本书并发拆解

98 段一段一段手跑不现实。所以有**分派 + 分片 + 合并**：

```
plan          看板：哪几段完成、还差几段
claim-batch   领一批（默认 4 段，上限 20）——每段自包含，可直接给一个子智能
accept-part   收某段的结果（index=N）
merge         合并成全书的图
reset-parts   清掉所有分片重来
```

**分片存储**：`设定/逻辑图分片/第NNNN段.json`，一段一个文件。

- 中断能续：重启后 `plan` 一眼看出哪几段完成了
- 失败能重跑：坏 JSON 也存档（标 `failed`），`claim-batch` 会重新派它
- 并行不互相覆盖：每段独立文件

**合并去重**：不是简单拼接。同一个「江哲」在三段里出现，合并后只有**一条**节点，`sources` 取并集（`第1段·第一章.md`、`第5段·第三章.md`…）。连线会按段做 id 重映射，所以合并后端点仍然对得上。

### 分段多选

分段格子**点一下选中、再点取消**，可以多选。选中的加蓝框。

选中后出现批量操作栏：

```
已选 3 段  5、7、9  [全选] [全不选] [载入第一段正文] [派发给子智能体拆解]
```

**单击 = 选中**，**双击 = 载入该段正文**（保留原来的快捷方式）。

### 固定的拆文子智能体

`~/.dsh/.agent-presets/novel-deconstructor/` —— 一个**固定 preset**，不是每次临时拼提示词。

为什么要固定：

1. **拆解标准要稳定** —— 98 段由 98 次调用产出，标准一漂合并时全是矛盾
2. 人格固定后，不同段的判断尺度一致，合并去重才有意义
3. 每次派发只需给「第几段 + 正文」，不用重复交代规则

它的 `/persona` 里写死了：七类节点、**每个节点必须标出处**、**body 至少 30 字**、
至少覆盖 world/character/structure、**空结果比编造的好**。

### 派发

勾选若干段 → 点「派发给子智能体拆解」→ 拿到一份派发说明：

```
# 拆解任务：随波逐流之一代军师.txt
共派发 3 段。每段交给一个「拆文子智能体」独立拆，互不干扰。

> 一个子智能体只拆一段。让它一次读多段，抽出来的判断标准会漂，
> 合并时互相矛盾，而且那种矛盾在合并后的图里根本看不出来。

## 第 1 段 ｜ 第一部 南楚状元 序章
- 正文 18439 字，4 章
- 取正文：novel_logic_map(action=chunk, chunkIndex=0)
- 收回产出：novel_logic_map(action=accept-part, index=0, text=<JSON>)
```

派发时每段立刻标 `running`（界面变橙并开始倒计时），**不会重复派**同一段
（已拆完和已在拆的都跳过，要重派带 `force`）。

### 看板：进度、倒计时、分段标绿

逻辑图面板顶部有一块看板：

```
全书 98 段  [完成 2] [在拆 1] [失败 0] [待拆 95]  58 个节点  [刷新]
[1][2][3][4][5]...[98]        ← 分段格子，按状态上色
在拆：第 3 段（剩 87 秒）
绿=已拆完且已进指令库　蓝=已拆完　橙=在拆　红=失败　灰=待拆
```

**五种颜色各有含义**：

| 颜色 | 状态 |
|---|---|
| 绿 | 已拆完**且**已进指令库 |
| 蓝 | 已拆完，还没进库 |
| 橙（带脉冲） | 在拆，鼠标悬停看剩余秒数 |
| 红 | 失败（悬停看原因） |
| 灰 | 待拆 |

点任一格子就把那一段正文载入素材框。

### 倒计时

领任务时记下 `startedAt` 与 `etaMs`（按每 5000 字约 60 秒估），界面据此显示剩余秒数。

- 只在**有段落在拆时**才跑心跳（没在拆就不浪费重渲染）
- 到点没完成显示「已超预期，可能还在跑」——**不谎报完成**
- 计时是**估算**，不含模型实际耗时波动，只用来判断「还要不要等」

### 拆完就进指令库

每收下一段，可以立刻用 `part-to-library` 把它送进指令库，不用等全书合并。

条目带 `段:N` 标签，所以：

- 指令库里能看出「这条来自第几段」
- 看板能反查「哪些段已经进库」→ 标绿
- `parts-in-library` 返回 `{ 段号: 条目数 }`，界面据此上色

### 多子智能协作

`collaborationBrief(98, 4)` 会给出分工说明：

```
全书 98 段，每次并发 4 段，共 25 批。
每个子智能只拆自己领到的那几段，产出的 JSON 单独贴回来 ——
不要一个子智能读多段（上下文会串味，不同段的判断标准会漂移）。
```

**「一个子智能只拆一段」是硬要求**。让它一次读多段，抽出来的标准会漂，合并时互相矛盾——那种矛盾在合并后的图里根本看不出来，只会让整张图变得不可信。

### 整本小说怎么处理

一本 54 万字的小说塞不进一次提示词，所以有**分段**：

```
[把本地书切段]  1545748 字　239 个章节标题　98 段
[1] [2] [3] [4] ...   ← 点一段，正文载入素材框
```

按**章节标题**切（第X章 / 第X回 / 序章 / 楔子 / 番外），每段控制在 2 万字以内。没有章节标题就按字数硬切，并说明。

实测你那本《随波逐流之一代军师》：239 个章节标记 → 切成 98 段，每段 3—4 章、约 1.8 万字。一段一段拆，最后合成一张图。

**编码自动识别**：本地 txt 十有八九是 GBK，直接按 UTF-8 读会得到一屏乱码。而且**乱码进库比读不到更坏**——统计全错还看不出来。所以先试严格 UTF-8，不行再试 GBK，判据是**乱码率**（汉字占一成以上、坏字符不到百分之一）。

### 图长什么样

不是插画，是**能驱动写作的结构化知识图**。每个节点归到一个槽位功能点：

| 节点类型 | 喂给哪个槽位 | 抽什么 |
|---|---|---|
| `world` | World Builder | 力量体系、代价、限制、社会结构 |
| `character` | Character Designer | 表面欲望、真实需求、致命缺陷、压力档反应 |
| `structure` | Chapter Pack | 章节骨架、信息差、钩子、张力曲线 |
| `style` | Style Anchor | 句长、节奏、感官、比喻 |
| `trope` | Chapter Pack | 可复用的情节机关 |
| `rule` | Review Pass | 禁止事项、必须满足的约束 |
| `material` | Chapter Pack | 专有名词、地名、器物 |

存成两份：`设定/小说逻辑图.md`（人读，带 mermaid 结构图）+ `.json`（条目从它来）。

### 一条硬判据：必须能追到出处

每个节点都要标 `sources`（来自哪份素材、哪一章）。**追不到出处的不要写**——那是模型编的，不是这本书的。

校验会明确提醒「没标出处 —— 无法确认是原文里的还是模型编的」。

### 两套类型体系要显式映射

图的类型按「喂给哪个槽位」分（有 `world`），指令库按「指令的用途」分（没有 `world`）。

不映射的话 `world` 会被指令库当成非法类型**静默回退成 `rule`**——世界规则变成硬规则，看着没错但语义全歪。所以有 `NODE_TO_LIB_KIND` 这张表，`world → material`。

### 图来的条目默认启用

和「从工作目录提取」相反：提取的是**原料**（默认不启用），图里的是**加工过的结论**（默认启用）。

## 指令库：最终写作指令的落点

这是**闭环**所在，也是你要的那个页签：

```
多次读小说（本地/网上）
      ↓  拆文入库：读一本，抽出**可执行指令**
   落成条目（一条一个文件）
      ↓  清单里勾选
   合成最终写作指令  ← 拿去写，写每一章都带着它
```

### 判据：是指令，不是资料

这是整条链上最要紧的一条，写在提示词里也写在条目校验里：

| ✗ 资料（给人读的感想） | ✓ 指令（能被执行） |
|---|---|
| 这本书节奏很好 | 每章至少一次信息差变化，且必须落在那条被点亮的信息上 |
| 打斗场面描写精彩 | 打斗不写招式名，只写身体的反应（呼吸、手抖、脚下的碎响） |

正文太短的条目会被提醒——那多半是资料，不是指令。

### 清单从哪来：从工作目录提取

库空着没用。所以指令库页签上有 **从工作目录提取素材**：

```
[先看看能提取什么]  [从工作目录提取素材]
```

扫描 `素材/` `拆文库/` `样本/` `设定/`，把文件变成条目：

| 目录 | 归成哪一类 |
|---|---|
| `素材/` | 素材 |
| `拆文库/` | 结构 |
| `样本/` | 文风 |
| `设定/` | 素材 |

**训练越多，清单越长** —— 读进来的小说、拆出来的东西、攒的样本，点一下就进清单。

提取出来的**默认不参与合成**（标着「待整理」）。这是刻意的：**原文不是指令**。实测把 13 篇原文直接合成，出来 38441 字，全是小说正文——那种「指令」只会把提示词撑爆、把真正的约束淹掉。

提取是**原料**，加工是你（或拆文入库）的事。整理成可执行的句子后，勾上它才进合成。合成时会提示「另有 N 条待整理没算进来」。

### 送到写作槽位

每个类型对应几个槽位（`SLOT_KINDS`）：

| 槽位 | 用得到 |
|---|---|
| Chapter Pack | 结构、人物、桥段、文风、硬规则、素材 |
| Review Pass | 结构、人物、硬规则 |
| De-AI Polish | 硬规则、文风 |
| Style Anchor | 文风、硬规则、素材 |
| World Builder | 素材、硬规则 |
| Character Designer | 人物、硬规则、素材 |

**选中某个槽位时，写作槽位页签里会列出它用得上的条目**，勾选即参与该槽位的指令，点「合成该槽位指令」就把它们拼成一份。

这样写第 N 章时，可以把跟这一章相关的那几条单独拎出来用，而不是把整库都塞进去。

### 六种类型

| 类型 | 装什么 |
|---|---|
| **硬规则** | 禁止事项、必须满足的约束（合成时排最前） |
| **文风** | 句长、节奏、感官偏好、比喻落点 |
| **结构** | 信息差、钩子、张力曲线、章节骨架 |
| **人物** | 压力反应、共情锚点、声音指纹 |
| **桥段** | 可复用的情节机关与转折设计 |
| **素材** | 设定、名词、灵感碎片（合成时排最后） |

### 页面做什么

- **清单**：勾选要参与合成的条目，可按名/说明/来源/标签筛，全选/全不选
- **逐条管理**：编辑（名/类型/说明/正文）、启用停用、删除
- **合成最终指令**：把勾选的按类型优先级拼成一份，可复制
- **拆文入库**：贴小说正文 → 生成提示词 → 模型产出 JSON → 贴回导入

### 两个顺序是分开的

- **列表**按**加入顺序**（`order = 上一条 + 1`）
- **合成**按**类型优先级**（硬规则 → 文风 → 结构 → 人物 → 桥段 → 素材），同类内维持加入顺序

这两个需求不同，一开始我混在一起，结果同类型条目顺序随机。分开之后各归各。

### 去重：按内容身份，不按 id

条目的身份是**「类型 + 归一化名字」**，不是 id。

id 带时间戳与随机后缀，每次导入都不一样——拿它判重等于每次都认为「这是新条目」。

**这是我踩过最贵的一个坑**：第一版导入时「已存在就换个 id 存新的」，逻辑图重导几次之后，**191 条里 147 条是重复的**（同一个「江哲」存了 7 份）。

现在三种策略（`onDuplicate`）：

| 策略 | 行为 |
|---|---|
| `update`（默认） | 同内容就更新已有条目，标签与出处取并集，正文保留更长的 |
| `skip` | 已有就跳过 |
| `new` | 强制存成副本（只在明确要一份副本时用） |

`dedupe` 可以清理历史重复：保留**信息最全**的那条（正文最长 → 标签最多 → 更新时间最新），把其余条目的标签与出处并进去再删。

### 提取也要去重

提取按**文件名**判重，不按「来源目录 + 名字」。

同一篇原文常同时躺在 `素材/` `拆文库/` `样本/` 里（我先放素材，又复制一份到样本），按目录判会被提取三次，得到三条同内容的条目。

### 存储

`<工作目录>/指令库/<id>.json`，**一条一个文件**。

不塞进一个总 JSON：那样两条同时写就互相覆盖；一条一个文件，坏一条也只坏一条（`list` 会把读不出的如实报出来，不影响其他条目）。

导入时对已有条目**不覆盖**——宁可存成新条目，也不悄悄改掉你调好的那条。

## 产出怎么进到写作槽位

把文件落进分类目录只是第一步 —— **槽位得知道自己手里有什么**。所以「写作槽位」页签顶部有一块**工作区现状**：

```
工作区  /home/wsn/文档/dsh/本地演示/novels/插件目录拆解
[下一步] 样本目录里有 2 篇 —— 先跑 Style Anchor，把文风基线定下来。
         [用样本目录跑 Style Anchor]
样本 2  细纲 0  正文 0  拆文库 2  素材 3
```

三个作用：

1. **告诉你下一步做什么** —— 按现有素材推一条最该做的（有样本没基线 → 推 Style Anchor；有细纲没正文 → 推 Chapter Pack；有正文 → 推审稿去味）
2. **一键取素材** —— 选 Style Anchor 时给「用「样本/」里的 N 个文件」，直接把路径填进样本列表；选 Chapter Pack 时列出细纲文件，点一个填章号
3. **每个槽位卡片上标出「手里有什么」** —— 就绪 / 缺东西一眼可见

盘点接口：`GET /api/dsh-writing-slots/slots/inventory`

## 阅读器

从 [dsh-reader](https://github.com/Wodexinhaoleng-Kasssa/dsh-reader)（Apache-2.0）移植。在线搜书、逐章阅读、整本 TXT 下载，也能读工作目录里的本地书。

### 状态会记住

- **搜索结果**：搜完就落盘，切页签、刷新、重启都还在。**新搜索会先清掉旧结果**再写新的。搜书页有「清掉结果」按钮。
- **阅读进度**：当前书名、目录、读到第几章、最近 20 条消息都会记住，回来接着读。
- **阅读子页签**：也记住，回来还在离开的那一页。

存在浏览器 localStorage，超配额时静默降级（不会因为存不进就把界面搞崩）。

**读完一本想再挑一本时，结果不会被清掉** —— 点书只会切到阅读页，搜书页的结果原地保留。

### 清除按键

| 按钮 | 在哪 | 清什么 |
|---|---|---|
| **清屏** | 阅读页导航条 | 清空对话；书和进度都还在，点「下一章」就能继续 |
| **清掉结果** | 搜书页 | 清掉搜索结果，localStorage 里的记录一并删掉（不会被自动捞回来） |

### 界面

章节以**对话消息**呈现，输入框支持指令：

```
下一章 / 上一章 / 第N章 / 目录 / 下载 / 清屏 / 书架
拆文 / 样本 / 素材        ← 把当前这章送进工作目录
<书名>                    ← 直接当搜索词
```

每条章节消息旁边有三个按钮：**拆**（送拆文库）、**样**（送样本，Style Anchor 语料）、**材**（送素材）。

### 和写作流程打通

这是它比独立阅读器多出来的价值：

| 动作 | 落到哪 | 用途 |
|---|---|---|
| 送拆文 | `拆文库/` | 拆结构：信息差、钩子、情绪曲线 |
| 送样本 | `样本/` | Style Anchor 读它统计文风 |
| 送素材 | `素材/` | 选题、灵感参考 |

落盘前**先过检查**：字体混淆内容、中文少于 50 字的一律拒绝——**进语料库会污染统计，而且看不出来**。

「本地书」页签同时列两处：工作目录的 `本地书/`（TXT）和 `章节/`（**你自己写的稿子**）。

### 书源的来源与风险

⚠ 内置 41 个书源，规则数据移植自 dsh-reader，其来源是 binbyu/Reader 公开的 `bs.json` / `.bs_bak.json`。

**这些源大多指向第三方聚合站**（笔趣阁系、00shu、12xs、蚂蚁文学、玄幻阁…），上游作者明确声明「注明出处、**严禁非法与商业用途**」。界面里把晋江这类正规平台标 ✅，其余不标注但来源可查。

- 书源随时可能失效（原版 README 同样警告）
- 取不到时**如实报错**，不伪造内容
- **不做任何反爬绕过**：引擎就是普通的 `node fetch` + XPath，没有字体还原、没有挑战脚本破解
- 下载内容仅限个人学习使用，请尊重各站版权

| `lib/reader/xpath.js` | XPath 子集（`//`、`[@attr='v']`、`[position()>1]`、`/@href`、`|`）+ JSON 路径 |

## 小说网站

用**你自己的 cookie**去站点取内容，像正常人一样：真实浏览器头、站点之间自动节流（默认 1.5 秒）。

支持的站点（都实测过）：番茄、起点、晋江、七猫、纵横、知乎盐言。

### 一条明确的边界：不做反爬绕过

实测发现两类情况：

| 站点 | 现象 | 判定 |
|---|---|---|
| **起点** | 返回 209 字节，带 `probe.js` | 反爬挑战页，不是内容 |
| **番茄** | 书名里混了**私有区字符**（`\ue491`…），配 woff2 字体映射 | 字体混淆，还原要做字形识别 |

这两样都是站点**明确的防护**。本插件**不绕过**——不做字体还原、不破解挑战脚本。

能做的是**认出来，并如实报告**，然后给正当路径：

```
起点    ok=False kind=challenge    站点返回了反爬挑战页，不是内容
        判定: 响应体极小且含探针脚本
        建议: 在浏览器里登录起点中文网，把 cookie 复制进来再试
番茄    ok=False kind=obfuscated   文本被字体混淆（3313 个私有区字符）
        建议: 这一类是站点刻意的字体混淆，本插件不绕过
晋江    ok=True  kind=content       ← GBK 嗅探生效，无 cookie 也取到了
```

**为什么这条边界重要**：把乱码当内容存进语料库是最坏的结果——Style Anchor 会拿它统计「文风」，得出的基线全是错的，而且**看不出来**。所以宁可说「取不到」。

### cookie 是凭据

和 token 一样对待：

- AES-256-GCM 加密后落盘，文件 `0600`，目录 `0700`，密钥单独存
- 列表接口**只回打码值**（前 6 后 4），永不回显明文
- 被改过的密文解不开（GCM 认证），换密钥也解不开
- 已有 cookie 文件读不了时**不覆盖**，先报错

### 按插件功能分类填充

这是「内容也可以按插件功能分类填充」的落点。判断一段内容该喂给哪个槽位：

```
1770 字、1260 中文、90 段、含对话=true
  → style_anchor / sample_corpus：1260 字、90 段，够当文风样本
  → style_anchor / 样本/：存进「样本」目录，Style Anchor 直接读
  → deai_polish / text：可以过一遍去味，看命中多少条规则
  → prose_sanity / text：先跑确定性检查（截断/工程词）
  → character_designer / existing：含对话，可用来抽人物声音指纹
```

**落盘前先过一遍检查**：混淆内容、空内容一律拒绝（实测：120 个私有区字符的内容被挡在语料库外）。`force=true` 才允许强写。

### 榜单解析是启发式的

站点结构各异，抽不准时返回**空数组**而不是硬凑，并给出 `confidence`。第一版把「关闭」「完结作品」这些导航按钮当成书名抽出来了——现在有导航词表过滤，且非内嵌数据的解析标 `low`，界面提示「建议人工看一眼」。

## 自动续跑

从 `@weibaohui/dsh-continue` 完整移植（原插件是这条赛道上功能最全的）。agent 会话中断后自动续上，不用手敲「继续」。

### 核心：有序规则表

**从上到下匹配，先命中先用**。不同失败类型走不同策略：

| 失败类型 | 默认动作 | 说明 |
|---|---|---|
| 限流（429） | 继续续跑 | 指数退避，**尊重服务商给的 Retry-After**，最多 5 次 |
| 额度耗尽 / 余额不足 | 止损通知 | 白重试没意义，立即交回人工 |
| 鉴权失败（401/403） | 止损通知 | 同上 |
| 上下文超限 | **压缩上下文后续跑** | 压缩服务**懒解析**；没挂后端就降级为一行通知 |
| 服务端错误（5xx） | 继续续跑 | |
| 传输/网络错误 | 继续续跑 | |
| 崩溃孤儿轮 | 继续续跑 | |
| 输出截断（max-tokens） | 继续续跑 | 长回复 / 长代码不再停在半截 |
| 自定义状态码 | 用户指定 | 数字匹配 HTTP 状态码，文字匹配机器码，大小写不敏感 |
| 任意失败 | 继续续跑 | 兜底 |

**顺序即优先级**：把「自定义状态码」放在「服务端错误」上方，特定码就会先走专属策略。界面上的规则编辑刻意做成一行一条 + 上移下移，因为顺序错了策略就错了。

### 四种动作

- `continue` — 续跑
- `continue-with` — **换模型**续跑（规则里指定 provider + model；本题连续失败后可切到备用模型）
- `compact` — 先压缩上下文再续跑
- `stop` — 止损并通知

### 退避与冷却

`base × 2^attempt`，上限 `backoffMaxMs`，加 0—20% 抖动（让并发重试错开）。限流时取 `max(退避, providerRetryAfterMs)`。

**冷却窗口内到达的失败是推迟，不是丢弃。** 这条容易做错：续跑轮自己的失败几乎必然落在冷却窗口里，丢弃会让会话只续一次就停摆。

### 客户端页签：停用即隐藏

设置页顶层两个页签：**写作槽位**（常驻）与**自动续跑**（只在启用时出现）。

停用后这个页签从界面消失，落回写作槽位。重新启用走 `auto_continue` 工具（`action=enable`）。一个不工作的功能不该占着导航。

### 移植时保留的硬约束

| 约束 | 为什么 |
|---|---|
| `source.kind` 非空且自有 | v4 准入拒 `plugin` 兜底 |
| 通知带 `id` + `role: 'user'` | **少了这两个，写入时静默通过，但整个会话下次加载会拒载**（"lacks an identified message"）。最阴的一条 |
| `append` 带 `surfaceOp: 'append'` | 不加宿主丢弃 |
| `followup` 延到分发窗口之外 | 宿主拒重入 append |
| 压缩服务懒解析（`ctx.get`） | 写进 `inject` 会让本插件在没挂压缩后端的 profile 上永久 pending |
| 排除 `subagent` 与宿主循环评审会话 | 子代理归父代理管 |

### 移植怎么验的

不只跑自己的测试，还用**原插件做差分比对**：

- 默认规则表、默认配置 —— **逐字节一致**
- 失败分类（16 个样例）、`codes` 解析与匹配 —— 一致
- `decideTurnEnd` 路由决策（16 个场景）—— 一致，包括「限流用尽后回落到 `any` 规则」这种细节

环境里装了原插件就自动比对；干净克隆里没有它，那一节会跳过。
